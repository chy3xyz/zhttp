# HTTP/3 (`httpz.h3`)

QUIC transport and HTTP/3 protocol support via ngtcp2 + nghttp3 C bindings.

**Import path:** `httpz.h3`

Off by default: build with `-Dh3=true`. Without it the `httpz.h3` namespace is empty and `libngtcp2`/`libnghttp3` are neither translated nor linked.

## Architecture

```
httpz.h3.Client / httpz.h3.Server     ← composed API
httpz.h3.http3.Session                ← HTTP/3 framing (QPACK, headers, data)
httpz.h3.quic.Connection / Listener   ← QUIC transport (UDP, crypto, streams)
httpz.h3.quic.TlsSession              ← OpenSSL session wired into one QUIC connection
```

---

## QUIC Layer (`httpz.h3.quic`)

```zig
/// Failure modes a connection can report. `TlsError` covers a failed handshake
/// (the alert and the TLS library's code are in `lastTlsFailure`),
/// `HandshakeTimeout` a handshake that never happened, `Http3Error` a
/// connection error from the HTTP/3 layer, and `ConnectionDropped` /
/// `RetryRequired` the two codes `ngtcp2_conn_read_pkt` documents that a server
/// must act on.
pub const Error = error{
    QuicError,
    OutOfMemory,
    NoSpaceLeft,
    TlsError,
    HandshakeTimeout,
    Http3Error,
    ConnectionClosed,
    ConnectionDropped,
    RetryRequired,
};

/// TLS settings for a QUIC client. `.{}` verifies the peer against the system
/// CA store; `insecure_skip_verify` is for local testing only.
pub const ClientTls = struct {
    root_ca: RootCa = .system,
    insecure_skip_verify: bool = false,
};

/// Create a QUIC client connection and drive the handshake.
pub fn connect(host: []const u8, port: u16, stream_ctx: ?StreamDataCtx, early_data: ?[]const u8, tls: ClientTls) Error!Connection

/// Load the server certificate used by every incoming connection.
pub fn setServerCert(cert_pem: []const u8, key_pem: []const u8) !void

/// Read one datagram / write pending packets / drive QUIC timers.
pub fn readPacket(conn: *Connection) Error!void
pub fn flushPackets(conn: *Connection) Error!void
pub fn handleExpiryIfDue(conn: *Connection) void

/// Event-loop helpers: wait for the socket without a fixed sleep, take the
/// datagrams already waiting instead of one per turn, and see how long is left
/// until the connection's next QUIC timer.
pub fn pollReadable(fd: posix.fd_t, timeout_ns: u64) bool
pub fn readAvailablePackets(conn: *Connection) Error!usize
pub fn expiryDelayNs(conn: *Connection) ?u64

/// Fill `buf` with cryptographically secure random bytes: the libc primitive
/// where the target has one, the `getrandom` syscall otherwise.
pub fn fillRandom(buf: []u8) void
pub fn getExpiry(conn: *Connection) ?u64
pub fn handleExpiry(conn: *Connection) Error!void

/// Pack one QUIC datagram with everything pending in the HTTP/3 session and
/// send it; returns the bytes sent, or 0 when ngtcp2 had nothing to put on the
/// wire (congestion or flow control) and the caller must stop pumping.
/// `NGTCP2_WRITE_STREAM_FLAG_MORE` keeps the packet open across the calls that
/// fill it, so a header block and the body behind it share one datagram.
pub fn writePackedPacket(conn: *Connection, h3_conn: *nghttp3.nghttp3_conn, ts: u64) Error!usize

/// Tell the peer the connection is going away, and answer its retransmissions
/// with the same frame during the closing period.
pub fn sendConnectionClose(conn: *Connection, error_code: u64, reason: []const u8) void
pub fn resendConnectionClose(conn: *Connection) void
```

`Listener` owns the UDP socket, the bound address and the connection-ID routing
table (`connections`), keyed by every connection ID that belongs to a
connection. `destinationCid` extracts the ID a datagram is addressed to (long
and short headers), `initPath` builds a network path for ngtcp2.

## HTTP/3 Layer (`httpz.h3.http3`)

```zig
pub const H3_NO_ERROR: u64 = 0x0100;

pub const Session = struct {
    conn: *nghttp3.nghttp3_conn,
    allocator: std.mem.Allocator,
    server: bool,
    /// Server side: requests received, in arrival order.
    requests: std.ArrayList(*ServerRequest),

    pub fn init(allocator: std.mem.Allocator) !*Session
    pub fn initServer(allocator: std.mem.Allocator, max_client_streams_bidi: u64, max_body_bytes: usize) !*Session
    pub fn deinit(self: *Session) void

    /// Each endpoint opens and binds its own control and QPACK streams.
    pub fn bindControlStream(self: *Session, stream_id: i64) !void
    pub fn bindQpackStreams(self: *Session, enc_stream_id: i64, dec_stream_id: i64) !void

    /// Client: submit a request, filling |state| from the response callbacks.
    /// |body| is read back through the state during the write pump, so it has
    /// to outlive the call; |headers| are encoded during it.
    pub fn submitRequest(
        self: *Session,
        stream_id: i64,
        method: []const u8,
        path: []const u8,
        authority: []const u8,
        headers: []const HeaderField,
        body: []const u8,
        state: *ResponseContext,
    ) !void

    /// Server: answer |req|, taking ownership of |body| until the stream closes.
    pub fn submitResponse(self: *Session, req: *ServerRequest, status: u16, content_type: []const u8, headers: []const HeaderField, body: []const u8) !void

    /// Server: answer |req| from a reader that produces the body as it is sent.
    /// No content-length goes out, and only the chunks the peer has not
    /// acknowledged yet are held.
    pub fn submitStreamingResponse(
        self: *Session,
        req: *ServerRequest,
        status: u16,
        content_type: []const u8,
        headers: []const HeaderField,
        body_reader: BodyReader,
        body_context: ?*anyopaque,
    ) !void

    /// Fill |buf| and return how many bytes were written, 0 at the end of the
    /// body.
    pub const BodyReader = *const fn (context: ?*anyopaque, buf: []u8) anyerror!usize;

    /// Largest chunk one call of a `BodyReader` can produce.
    pub const stream_chunk_bytes = 64 * 1024;

    /// Feed received stream data to nghttp3.
    pub fn readStream(self: *Session, stream_id: i64, data: []const u8, fin: bool) !usize
};
```

`ServerRequest` holds a request's `method`/`path`, its header fields and body, and
the response being sent: the body itself for `submitResponse`, and for
`submitStreamingResponse` the reader, the buffer it fills and the chunks that
have been handed to nghttp3 but not acknowledged yet. Everything it owns lives in
one arena, so a request is released with a single `deinit`. The peer's inbound
unidirectional streams are identified by nghttp3 itself from their stream-type
prefix.

## Client (`httpz.h3.Client`) / Server (`httpz.h3.Server`)

```zig
pub fn Client.init(allocator: std.mem.Allocator, host: []const u8, port: u16, tls: quic.ClientTls) !Client
pub fn Client.deinit(self: *Client) void
/// GET |path|, return the response body (caller owns it).
pub fn Client.get(self: *Client, path: []const u8) ![]const u8
/// GET |path|, returning the status, the header fields and the body.
pub fn Client.request(self: *Client, path: []const u8) !Answer
/// Any method, with header fields and an optional body.
pub fn Client.send(self: *Client, method: []const u8, path: []const u8, headers: []const Header, body: []const u8) !Answer

pub const Answer = struct {
    status: u16,
    /// `name: value` lines separated by CRLF, `:status` first.
    header_text: []const u8,
    body: []const u8,
};

pub const Header = struct { name: []const u8, value: []const u8 };  // names lowercase

pub const Options = struct {
    /// Connections quiet for this long start closing.
    idle_timeout_ns: u64 = 30 * std.time.ns_per_s,
    /// How long a closing connection sticks around to answer the peer.
    closing_period_ns: u64 = 3 * std.time.ns_per_s,
    /// Largest request body accepted; a larger one is answered with 413.
    /// The body is buffered in full before the handler runs, so this is what
    /// bounds the memory one request holds.
    max_request_body_bytes: usize = 1024 * 1024,
};

/// A received request: `:method` and `:path` folded in, every other field in
/// `headers` in the order it arrived, and the body. Valid until the handler
/// returns.
pub const Request = struct {
    method: Method,          // httpz.Request.Method
    path: []const u8,
    headers: Headers,        // httpz.Headers — .get("name") works as elsewhere
    body: []const u8,
};

/// What a handler answers with. `body` is copied, so it may be a literal or a
/// buffer the handler owns.
pub const Response = struct {
    status: StatusCode = .ok,        // httpz.Response.StatusCode
    content_type: []const u8 = "text/plain",
    body: []const u8 = "",
    /// Streams the body instead of handing it over: called when the stream has
    /// room for more, fills `buf`, and returns how many bytes were written — 0
    /// at the end. `body` is then ignored and no content-length goes out
    /// (RFC 9114 Section 4.1 lets an HTTP/3 response leave it out). Called from
    /// the server's event loop, so it must not wait long for more data.
    body_reader: ?*const fn (context: ?*anyopaque, buf: []u8) anyerror!usize = null,
    /// Passed to `body_reader`.
    body_context: ?*anyopaque = null,
    /// Sent after Content-Type, e.g. Set-Cookie or Location (names lowercase).
    /// A content-length here is dropped: the body's length is what goes out.
    headers: []const Header = &.{},
};

/// Handler called for each completed request. A request whose method is not one
/// of the known ones is answered with 501 without the handler being called.
pub const Handler = *const fn (allocator: std.mem.Allocator, request: *const Request) Response;

pub fn Server.init(allocator: std.mem.Allocator, port: u16, handler: Handler, options: Options) !Server
pub fn Server.deinit(self: *Server) void
pub fn Server.run(self: *Server) !void
/// Ask `run` to come back and close what it was serving.
pub fn Server.stop(self: *Server) void
```

`Server.run` is a single-threaded event loop. Each turn it waits in `poll` for
the nearest of the socket becoming readable, a connection's next QUIC timer, or
the reap interval; when the socket is readable it drains up to
`quic.max_datagrams_per_drain` datagrams instead of one, so a peer that sends
faster than one datagram per wakeup is not throttled by the loop. It then
services every connection (own H3 streams, pending requests, queued writes, QUIC
timers) and periodically closes connections that went idle and reaps those whose
closing period is over. A connection that stops talking is told so with a
CONNECTION_CLOSE, which is then re-sent in answer to anything it still sends.

`Server.stop` sets a flag the loop reads between turns, so a server started on
one thread can be taken down from another; the loop can be waiting in `poll` for
up to a second when nothing is happening. It is a stop rather than a graceful
shutdown: requests in flight are cut off instead of being drained, and peers get
the CONNECTION_CLOSE rather than a GOAWAY. `run` closes what it was serving
before it returns, so the server can be `deinit`ed as soon as the thread has
been joined.

A handler that sets `body_reader` streams its response instead of handing over a
body: the server calls the reader whenever the stream has room for more and sends
what it returns as it goes, so a response may be larger — or longer-lived — than
anything the server could hold in memory. Each chunk is copied onto a buffer of
its own, and that buffer is only reused once the peer has acknowledged the bytes
it holds, which is what ngtcp2 needs to retransmit a lost packet; a stream
therefore holds the chunks in flight — bounded by the peer's flow control window
— plus the reader's own buffer. No `content-length` is sent: RFC 9114 Section 4.1
lets an HTTP/3 response leave it out, and the length is not known before the
reader has reported the end of the body.

## Usage Example

```zig
const std = @import("std");
const httpz = @import("httpz");
const h3 = httpz.h3;

fn handle(allocator: std.mem.Allocator, request: *const h3.Server.Request) h3.Server.Response {
    _ = allocator;
    if (request.method != .GET) return .{ .status = .method_not_allowed, .body = "only GET\n" };
    if (std.mem.eql(u8, request.path, "/health")) return .{ .body = "ok\n" };
    // request.headers.get("content-type"), request.body — the whole request.
    return .{ .status = .not_found, .body = "not found\n" };
}

pub fn main() !void {
    var gpa = std.heap.GeneralPurposeAllocator(.{}){};
    defer _ = gpa.deinit();
    const allocator = gpa.allocator();

    // Client (the last argument is the TLS configuration; `.{}` verifies
    // against the system CA store)
    var client = try h3.Client.init(allocator, "example.com", 443, .{});
    defer client.deinit();

    // Server
    try h3.quic.setServerCert(cert_pem, key_pem);
    var server = try h3.Server.init(allocator, 4433, handle, .{});
    defer server.deinit();
    try server.run();
}
```

## Pitfalls

Both libraries require more of the application than their function signatures
suggest. Everything below was found the hard way; the comments in `src/h3/`
point at the same places.

### ngtcp2 (QUIC)

- **Every callback the header calls mandatory must be set.** ngtcp2 asserts on
  a missing one inside `conn_new`, which aborts the process — that is how a
  missing `rand` showed up.
- **The `path` argument of the write functions must own its address buffers.**
  ngtcp2 stores the destination path there and requires each `addr` field to
  point at a `sockaddr_union`-sized buffer; a bare `ngtcp2_path` (null `addr`)
  crashes inside ngtcp2. Use `quic.initPath` / `ngtcp2_path_storage`.
- **The write functions only fill a buffer.** The application sends it
  (`writePackedPacket` and `flushPackets` do).
- **`NGTCP2_WRITE_STREAM_FLAG_MORE` decides the packet's shape, and every call
  that uses it must agree on everything.** With the flag a call leaves the packet
  open, which is how a header block, the body behind it and other streams end up
  in one datagram instead of one packet each; ngtcp2 requires the same path,
  packet info, buffer and timestamp on every call that adds to it.
  `NGTCP2_ERR_WRITE_MORE` means "offer me more", and nghttp3 has to be told what
  went out with `nghttp3_conn_add_write_offset`. The packet is finished by one
  more call with `stream_id` = -1 and nothing to offer.
  `NGTCP2_ERR_STREAM_DATA_BLOCKED` and `NGTCP2_ERR_STREAM_SHUT_WR` stop one
  stream only: block or shut that stream down in nghttp3 and carry on, or the
  packet being built is lost.
- **Sending is not writing.** ngtcp2's pacing is measured from
  `ngtcp2_conn_update_pkt_tx_time`, which the pumps call once per round that put
  packets on the wire; without it the connection never notices how much it sent.
- **Ask `ngtcp2_conn_get_max_data_left2` before offering data.** While the
  connection's own flow control window is empty ngtcp2 refuses every stream, and
  each of them has to be unblocked again later.
- **Never take one datagram per turn.** A loop that reads one datagram, services
  the connection and reads again is capped at one packet per wakeup; waiting in
  `poll` and draining up to `quic.max_datagrams_per_drain` datagrams
  (`readAvailablePackets`, `Server.drainSocket`) is what took the benchmark from
  256 to 3880 requests/s on a single connection.
- **`std.c.arc4random_buf` is a no-op on Linux.** In this std it is a
  `switch (native_os)` that resolves to an empty tuple — a call that does nothing
  — unless the ABI is Android or glibc >= 2.36, so a connection ID or the
  stateless reset secret filled through it holds whatever the memory happened to
  hold. `quic.fillRandom` uses the libc primitive where the target has one, the
  `getrandom` syscall otherwise, and refuses to compile where neither exists.
- **`ngtcp2_conn_server_new`'s `dcid` is the client's Initial *SCID***, not the
  DCID in that packet; the packet's DCID is what goes into
  `params.original_dcid` (RFC 9000 requires the server to echo it back).
- **`recv_client_initial` must install the Initial keys** ("generate initial
  keys and IVs for both transmission and reception") — delegate to
  `ngtcp2_crypto_recv_client_initial_cb`.
- **`ngtcp2_transport_params_default` zeroes everything.** HTTP/3's control and
  QPACK streams are unidirectional, so `initial_max_stream_data_uni` has to be
  set or not one byte of them can be sent (the write simply reports no data).
- **TLS has to be wired in by hand:** an `SSL_CTX`/`SSL` per connection,
  `ngtcp2_crypto_ossl_configure_{client,server}_session` on it,
  `ngtcp2_crypto_ossl_ctx_new`, `ngtcp2_conn_set_tls_native_handle`, and the
  `ngtcp2_crypto_conn_ref` (with `get_conn`) through `SSL_set_app_data`. ALPN
  `h3` is mandatory for QUIC.
- **The server's `SSL_CTX` is shared** (it comes from `setServerCert`), so a
  per-connection teardown must not free it — `TlsSession.owns_ssl_ctx`.
- **Routing has to handle long and short headers**, the client's *original* DCID
  (used until it learns ours) and every connection ID `get_new_connection_id`
  issues. A connection owns all of them; drop them together.
- **The closing state cannot write normally** (`write_pkt` returns
  `NGTCP2_ERR_CLOSING`, and `write_connection_close` returns 0 once closing):
  keep the CONNECTION_CLOSE packet and resend those bytes.
- **Timers are the application's job:** without `handleExpiryIfDue` in the loop
  nothing is ever retransmitted.
- **`ngtcp2_conn_read_pkt`'s return value is meaningful.** Besides ordinary
  failures it reports `NGTCP2_ERR_DROP_CONN` (drop the connection silently and
  discard its state), `NGTCP2_ERR_RETRY` (the server must send a Retry packet
  and discard the state) and `NGTCP2_ERR_CRYPTO` (a TLS error — read the alert
  with `ngtcp2_conn_get_tls_alert2`). Discarding the result leaves a connection
  that must be dropped in the routing table and turns a certificate failure into
  an anonymous error.

### nghttp3 (HTTP/3)

- **Each endpoint opens and binds its own control and QPACK streams** before
  submitting anything (`bindControlStream` + `bindQpackStreams`); otherwise
  `nghttp3_conn_submit_request` asserts on a missing QPACK encoder.
- **`nghttp3_conn_submit_request`'s nva only has to live until the call
  returns**, because the fields are encoded during it; the *body* does not. It
  comes back through the `nghttp3_data_reader` on a later write pump, so
  whatever `read_data` hands out has to outlive the call — the client keeps it
  in the stream's state, and its caller has to keep it alive until the request
  returns.
- **A request body that is refused still has to be credited.** nghttp3 counts
  what `recv_data` says the application consumed, and the datagram-level credit
  goes back to the peer in `onQuicServerStreamData` either way, so a server that
  drops a body over `max_request_body_bytes` must drop it *and* account for it,
  or the peer's window never opens again and the connection stalls.
- **`nghttp3_conn_add_write_offset` takes the *stream data* bytes** ngtcp2
  consumed — on every `NGTCP2_ERR_WRITE_MORE` as well as on a finished packet —
  and a packet may be written without any (`pdatalen == -1`).
- **A write pump must stop when it makes no progress.** `ngtcp2_conn_writev_stream`
  returning 0 means congestion- or flow-control limited, and looping on it spins
  forever and wedges the whole event loop. Mark the stream blocked with
  `nghttp3_conn_block_stream` and try again next turn — and note that a blocked
  stream is only offered again after `nghttp3_conn_unblock_stream`, which is why
  the ngtcp2 `extend_max_stream_data` callback is wired to it.
- **`nghttp3_conn_read_stream2`'s "consumed" count does not include DATA
  payloads** (`nghttp3_conn.c`, the DATA case advances the cursor without adding
  to `nconsumed`), so flow-control credit has to account for the payload
  separately — the bridges here credit the whole datagram, which is right
  because the application consumes every byte it is handed.
- **A negative return from `nghttp3_conn_read_stream2` means the connection must
  be closed** — calling anything but `nghttp3_conn_del` afterwards is undefined
  behaviour. Report it (`StreamRead.connection_error` carries the QUIC
  application error code from `nghttp3_err_infer_quic_app_error_code`) and tear
  the connection down; do not treat it as "consumed nothing".
- **The bytes `read_data` hands over are needed until the peer acknowledges
  them.** ngtcp2 keeps what it is given — "The caller must keep the portion of
  data covered by |*pdatalen| bytes intact until
  `acked_stream_data_offset` indicates that they are acknowledged" (ngtcp2.h) —
  and nghttp3 asks for the next chunk as soon as the previous one has been
  *written*, not when it has been acknowledged. A single buffer refilled on
  every call therefore sends the wrong bytes whenever a packet has to be
  retransmitted, which on a lossy link is corruption and not an error anyone
  sees. The server gives each chunk a buffer of its own and reuses it only after
  `nghttp3_acked_stream_data` says those bytes are acknowledged, which is why
  `Session` sets that callback.
- **Pass a real timestamp to `nghttp3_conn_read_stream2`.** It must be
  non-decreasing and come from a steady clock; passing 0 permanently defeats
  nghttp3's glitch rate limiter, which returns immediately when the timestamp
  repeats.
- **Sent data is only reclaimed on acknowledgement.** nghttp3 pops its per-stream
  outq from `nghttp3_stream_update_ack_offset` alone, so an application that
  never calls `nghttp3_conn_add_ack_offset` (fed by ngtcp2's
  `acked_stream_data_offset` callback) keeps every byte of a long-lived response
  in memory and never gets the documented ack notification.
- **Server requests need per-request state** created in `begin_headers`, marked
  complete in `end_stream`, answered with a `nghttp3_data_reader` whose body
  outlives the submit call, and freed in `stream_close`.
- **QUIC stream limits are not raised for you.** A server that advertises
  `initial_max_streams_bidi` and never calls `ngtcp2_conn_extend_max_streams_bidi`
  caps a connection at exactly that many requests; nghttp3 has to be told too
  (`nghttp3_conn_set_max_client_streams_bidi`, from the
  `extend_max_remote_streams_bidi` callback).
- **`get_new_connection_id` must fill the stateless reset token and honour the
  requested length.** Returning a short CID makes ngtcp2 reject it, and an
  unfilled token sends the peer uninitialized bytes (and disables stateless
  reset protection).

### Testing

- The tests in `src/h3/quic_test.zig` run a real server on a background thread.
  `Server.stop` makes the loop come back and close what it was serving, so a
  test can join the thread and `deinit` the server — the two tests that check for
  leaks do exactly that, with a `std.heap.DebugAllocator` that has to report
  `.ok` at the end. The rest leave their servers running, because stopping one
  can take up to a second (the loop waits in `poll`), and allocate with
  `std.heap.page_allocator` so the testing allocator does not report what is
  still in use as leaked.
- **Free what a request returns before the leak check, not in a `defer`.** A
  `defer` runs after the function's last statement, which is where the leak
  check sits; a body freed that way is reported as a leak.
- A `DebugAllocator` that does report a leak takes a long time to print the
  stack trace of every address, so a leak that looks like a hung test usually is
  one.
- Each test binds port 0 and reads the real port back from
  `server.listener.local_addr`. A server thread that is never stopped holds its
  socket for the life of the process, so fixed ports make two test processes
  fight over them (macOS needs `SO_REUSEPORT`, not just `SO_REUSEADDR`, for that
  to work).
- To let a connection go idle, configure `Server.Options` — the defaults
  (30 s idle, 3 s closing) are far too slow for a test.
- Do not read the server's routing table from the test thread; it is mutated by
  the server thread. Poll a thread-safe signal instead.
- `timespec.nsec` must stay below 1e9. A sleep helper written as
  `.nsec = ms * std.time.ns_per_ms` silently does nothing for `ms >= 1000`
  (`nanosleep` returns `EINVAL`), which makes a test that waits for a timeout
  pass or fail for the wrong reason.
- `zig build bench-h3 -Dh3=true` drives the same stack (`benches/bench_h3.zig`):
  500 small requests on one connection plus 2 MiB responses. Those two cases are
  what caught the write-pump wedge and the 100-request cap, so run it when
  touching the pumps, flow control or stream limits — and read both numbers: a
  pump that regresses into one packet per turn still passes, it just drops back
  to ~250 requests/s and ~1 MB/s.
